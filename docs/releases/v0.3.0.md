# v0.3.0 — Localization Baselines and Negative Results

Research milestone · 2026-10-08 · Package version 0.3.0.

This milestone adds a matched 4B/14B development comparison, two separately frozen
new-issue validation campaigns, and a cross-report synthesis. It records negative
findings alongside the earlier positive small-model baseline.

## Findings

| Population / intervention | 4B Recall@5 | 14B Recall@5 | Interpretation |
| --- | ---: | ---: | --- |
| dev-v2: 60 issues / 6 seen repositories, fresh unconstrained outputs | 0.6569 | 0.6091 | Larger-candidate improvement rule fails |
| validation-v1: 20 new issues / 5 seen repositories, free → constrained paths | 0.6333 → 0.6333 | 0.5958 → 0.6458 | No primary 4B improvement; 14B exploratory |
| validation-v2: 30 new issues / 4 seen repositories, constrained paths → scores | 0.6528 → 0.3222 | 0.6750 → 0.1389 | Tested score recipe substantially reduces quality |

These populations and treatments are distinct; the rows are not a pooled estimate
or performance trend. Every selected attempt remains in its quality denominator.

- On dev-v2, G-minus-S Recall@5 is −0.0478, repository-block 95% interval
  [−0.0790, −0.0281]. Strict successes are 30/60 versus 33/60. The fresh 4B run
  reproduces all 60 historical ranked-path/disposition/failure records.
- Candidate-path constraints eliminate unknown paths but allow duplicates. On
  validation-v1, 4B strict success remains 9/20 and every per-task recall difference
  is zero. The 14B gain +0.05 has exploratory interval [0, 0.15].
- On validation-v2, the primary 4B score-minus-path gain is −0.3306, interval
  [−0.5753, −0.1667]; strict successes fall 15/30 → 7/30. The exploratory 14B
  gain is −0.5361, interval [−0.6380, −0.4286], with strict 17/30 → 4/30.
  Both score arms produce 30/30 format-valid vectors. This tests the entire frozen
  prompt/representation/mapping recipe, not scoring methods or uniqueness alone.

The earlier positive result remains useful: untuned 4B improves dev-v2 Recall@5
from 0.2283 for matched-context lexical to 0.6569. It does not establish general
superiority to full-corpus lexical, specialization or full-system efficiency.

## Scope and next question

All model runs use exposed development repositories; later validation contains
new issues from seen repositories. Four to six repository blocks limit uncertainty.
Different post-training/conversion histories prevent model-size causality claims.
Strict success measures file-set coverage against one accepted patch, not repair.
Runtime isolation and duplicate exclusions do not rule out pretraining contamination.

Actual full-system cost per success, training, repository/time generalization,
fallback and downstream issue repair remain untested or unknown. The next proposed
question concerns candidate coverage and excerpt selection under a fixed evidence
budget, with matched controls and a new preregistered evaluation population.
